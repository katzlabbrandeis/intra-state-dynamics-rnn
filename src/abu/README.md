Ok, so: it's parquet time. There's a lot (too much) here, so I'm gonna start with a general schema for a set of dirs that I'm gonna refer to as "generated by RNNlatentprocessing", a big class that auto-generates the following data from either 1. input latents or 2. input firing rate vectors (see: /src/core/pre_processing/RNNLatentprocessing.py). When I say "generated by RNNlatentprocessing", the data within the subdirs are dictated by the following keywords/schema/whatever else. Keywords: 
- if "_warped": I attempted to use some sort of interpolation to warp all states to the same len across trials for a given taste. 
- if "_unwarped": data unmolested by a shitty interpolation 
- if "raw_output" OR "epoch_dataframes": UnPCA'd latents / firing rate vectors; "epoch_dataframes" is a legacy name that is being generated despite efforts to figure out why and stop it. They SHOULD be the exact same thing. Sorry for the confusion here. what happens with messy repos. 
- if "robust_pca_95": latents/fr vectors that have been run through PCA, keeping 95% of the variance of the original DS. The latents here are what you want. "robust_pca" is a legacy name and refers to the fact that all trials were concatenated, PCA run, and then de-concatenated for a given taste. 
- if "robust_pca_full": Same as "robust_pca_95", but keeping 100% of the variance from the transform. 
- if "first_derivatives": the first difference of the given vector 
- if "second_derivatives": the second difference of the given vector. 
- if "changepoints": changepoints. See above for how to access. 
- if "ttest": This was a new one that I added late. it is a MWU test between vectors to do the first half/second half split to determine if a vector is "dynamic". if you're curious, see line 1039 in RNNLatentprocessing for more. 

IN ALL CASES, use df = pl.read_parquet() to read a given parquet / all parquets in the given dir. Each df cell contains one (1) value per; do df.schema() to get the schema and df.filter(pl.col = 'col_name') and/or df['col'].unique() to get unique values. Historically, I'd read all of these dataframes into a dict (🤢) and then looped through it. See /src/core/utils/read_parquets.py for the functions that I used to read parquets into a dict of polars dataframes. Alternatively, there's a function in there that reads everything into one mega df. 

With that being stated: 

Analysis involving convolved firing rates (as inferred from spike trains) is entirely under /output/intermediate_files/FR_PROCESSING_PARQUETS, in here:
- rr_firing_uw_lite_rnn_outputs (sub-dirs here generated by RNNLatentprocessor). This is really probably where you want to pull data from. 
- spike_trains: spike trains, but in parquet form. 
- rr_firing_uw_lite_cleaned: the rolling window firing rates with some schema fixing and other cleanup. I believe this is usable data, if not entirely the most useful. 
- rr_firing_uw_lite: Unclean data, don't use. I was (and am) in the process of getting rid of this. 
- rr_firing_unwarped: don't bother with this. Go to rr_firing_uw_lite_cleaned and the dirs within there to get your actual convolved data. 
- spikes_warped: spikes, interpolated (??? not sure why I thought this would work)
- spikes_unwarped: unmolested spike train vectors. Currently unclear how this is different from spike_trains. Will update. 
- changepoints: changepoints.
